* Honest interpretation

1. *The de-saturation battery also saturated.* Despite fixtures
   deliberately built with a naive visible-passing/hidden-failing gap
   (confirmed structurally: each hidden suite runs 7 tests against 4-5
   visible tests, and the unpatched fixture fails both), the baseline
   single-provider agent solved all three hard tasks correctly on the
   *first* real attempt, passing both the visible suite and the larger
   hidden suite every time. It did not take the naive-patch bait in any
   of the three tasks. With baseline already at 3/3 hidden, the full
   harness (panel + verify gate) had nothing to rescue and produced an
   identical 3/3 hidden outcome -- this run still cannot answer whether
   panel+verify improves completion, only that it adds overhead when
   completion is already saturated.
2. *The overhead of the full arm this time is directionally the same as
   8e but noisier*: full arm's mean wall was +35.6s (+21%) over
   baseline, but mean cost was *lower* ($0.7893 vs $0.8149) -- the
   opposite sign from 8e's finding (there, full cost slightly more).
   This is most likely explained by baseline's hard1 run needing 2
   steps (extra distill-call cost) while every full run converged in
   1 step; it is not evidence that verify-gate overhead is negative,
   just that step-count variance at n=1 swamps the true per-step verify
   tax.
3. *A real architectural boundary surfaced in the digests, harmless
   here but worth flagging*: in 3 of 6 final digests (hard1-full,
   hard2-baseline, hard3-full) -- plus hard1-baseline's intermediate
   step-1 digest, self-corrected by step 2 -- the model's own
   step/distill narrative reports that a *second* attempt to re-run
   `make check` (as a self-check before finalizing) was blocked by
   "sandbox approval" -- e.g. hard2-baseline's digest: 「`make check`
   は全4テスト通過（このセッションでは対話承認が必要なため再実行未確認、
   次ステップで再検証推奨）」. Root cause: `:agentic` extras
   (`bypassPermissions`) are threaded into the step-function's/panel
   member's orchestrator task via `anvil-fusion--agentic-extras`, but
   `anvil-fusion-longrun--default-distill-fn` builds its
   `anvil-fusion-longrun--run-one` call with **no member-extras
   argument at all** -- the distill call always runs under the
   orchestrator's plain default (`acceptEdits`), never inheriting
   `:agentic`. In every run here this only affected a *redundant*
   self-re-verification the agent attempted after already having run
   `make check` successfully in the same step, so no run's correctness
   was harmed and the bash harness's own post-hoc `make check`/`score.sh`
   scoring (unaffected by any of this) still passed. But it means: if a
   future quest design relies on the *distill* phase (or the verify-gate's
   claim-extraction phase, which is a similarly bare orchestrator call)
   to independently re-run build/tests, it will hit the same silent
   permission wall the original 8e smoke hit in the step phase. This is
   a gap in the Phase 8f fix's coverage, not a bug in this eval's
   harness.
4. Cost accounting caveat (same as 8e): per-run `:cost-usd` sums every
   `anvil-orchestrator-extract-result` in the quest's dynamic extent
   (steps + distills + verify sub-calls) plus fusion-ask candidate
   costs (none fired, panel-steps=0 everywhere). Figures are lower
   bounds where a sub-call reported no numeric cost.

* Limitations

- n=1 per (task, arm): no variance estimate; a single sample per cell,
  same caveat as 8e.
- Ceiling effect persists even in the harder battery -- to discriminate
  the arms empirically, tasks need to defeat a modern Claude
  Code-driven step agent with real Bash/build access at a measurable
  rate. These fixtures defeat a *naive one-shot patch* (per the
  README's verification contract) but not an agent that can actually
  run `make check`, read its own failures, and iterate -- which is
  exactly what both arms here were granted via `:agentic 'force`.
- The panel path (opus-solo, hard-only gating) and the gate-retry path
  (REFUTED-claim feedback loop) were structurally reachable but never
  triggered in this battery either -- this eval does not validate their
  end-to-end behavior on a genuinely-hard case, only that they add
  bounded overhead and never fire spuriously.
- The distill-phase permission gap (finding #3 above) was observed as a
  narrated self-report inside the model's own digest text, not
  independently instrumented by this harness (no separate log of the
  distill call's raw stderr/permission-denial event) -- treat it as a
  strong qualitative signal, not a hard-instrumented count.
- Both arms again had full local build/test execution rights via
  `:agentic 'force`; results under the orchestrator's shipped default
  permission mode (`acceptEdits`, no override) would look categorically
  different, per the original 8e attempt-1 evidence.
