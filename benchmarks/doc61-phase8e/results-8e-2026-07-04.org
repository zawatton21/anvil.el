** Harness deviation found by the smoke run (attempt 1, task1/baseline)

The first smoke attempt ran with the orchestrator default
=--permission-mode acceptEdits=. A non-interactive =claude --print=
child can edit files under that mode but CANNOT run Bash -- every
=make check= attempt came back "requires approval". The step agent
produced a (retrospectively hidden-passing) patch within ~2 steps, then
burned steps 3+ re-verifying statically; its own digest concluded:

#+begin_quote
`make check`（Bash経由）を改めて実行し、「requires approval」で拒否され
ることを再確認（累計6回目）。… 親オーケストレーター側が承認済みモードで
`make check`を代行実行するか、… このサブタスクではこれ以上前進できない。
#+end_quote

The run was killed at step 4 ($2.65 spent, 708s wall); scoring the
leftover tree gave visible PASS + hidden PASS anyway (the patch was
already correct -- artifacts kept as
=raw/task1-baseline.attempt1-permblocked.*=). Fix (harness only, no
module touched): =(setq anvil-orchestrator-permission-mode
"bypassPermissions")= in the batch process, safe because every child
cwd is a throwaway scratch copy. Smoke was retried once per protocol
and passed end-to-end in 46s / 1 step / $0.33.

* Honest interpretation

1. *No separation between arms -- the benchmark saturated.* Both arms
   completed 3/3 hidden. The task calibration ("3-6 focused steps",
   visible-vs-hidden traps for superficial fixes) did not hold against
   a current sonnet step agent with shell access: it solved each task
   in 1-2 steps and never took the overfit bait (task 2's silent
   =pending -> approve= regression and task 3's spec-only requirements
   were all fixed from =TASK.md= + spec comments, not test-to-green
   hacking). With zero baseline failures there is nothing for the
   verify gate or panel to rescue; this eval cannot demonstrate (or
   refute) an Arm B advantage, only measure its overhead.
2. *The full harness's measured overhead at this difficulty*: +$0.03
   to +$0.16 and +10..50s per run (verify-gate claim extraction +
   check on a clean digest), for identical outcomes. =hard-only= mode
   correctly kept the expensive panel at 0 -- the cost discipline
   works, but that also means Phase 8b's panel path got zero
   end-to-end exercise here.
3. *The most consequential finding is the permission-mode blocker*,
   not the arm comparison: under the orchestrator default
   =acceptEdits=, a longrun coding quest that must RUN anything
   (build/test) cannot ever reach =STATUS: DONE= -- it converges to a
   loop of static re-verification and burned $2.65 / 8x the fixed-run
   cost before being killed. Any Doc 61 8x follow-up that points
   longrun at code tasks needs an explicit permission/allowed-tools
   decision (bypassPermissions in a sandbox, or an =--allowedTools=
   grant covering the build command) baked into the module or
   documented as a required knob.
4. Cost accounting caveat: per-run =:cost-usd= sums every
   =anvil-orchestrator-extract-result= in the quest's dynamic extent
   (steps + distills + verify sub-calls) plus fusion-ask candidate
   costs (none fired). Where a sub-call reported no numeric cost it
   contributes 0, so figures are lower bounds, though the claude
   stream-json path reports cost reliably.

* Limitations

- n=1 per (task, arm): no variance estimate; a single lucky/unlucky
  sample per cell.
- Ceiling effect (see above) -- to discriminate the arms, tasks need
  to be hard enough that the baseline fails hidden at a measurable
  rate (bigger codebases, cross-file inconsistencies, requirements
  hidden behind execution-only behavior, or a weaker/cheaper step
  model as the baseline).
- The panel path (8b) and the gate-retry path (8c's REFUTED feedback
  loop) were structurally reachable but never triggered; this eval
  does not validate their end-to-end behavior, only that they do not
  fire spuriously on easy tasks.
- The baseline arm also had =bypassPermissions=; the attempt-1
  blocker means results under the shipped default permission mode
  would look categorically different (0/6 quests able to self-verify).
- Step model was the orchestrator claude default (sonnet) for
  non-panel steps in BOTH arms; the arms differ only in panel/verify
  wiring, per the 8e design.
